# Medication source archive workflow — 2026-10-22

## Result

The prepared archive path now spans bounded HTTP input, validated caller-session projection, original-file verification, archive byte readback, atomic worker completion, a retained proof receipt, fresh confirmation under caller rights and historical download. Ready archives undergo byte verification and worker completion as well. No UI, Android or module release setting changes.

The previous adapter inserted archive metadata and invoked a separate caller-side finalizer. It now calls a single privileged worker RPC. Completion rechecks the current source, complete native order, document version, active session and permissions while holding row locks. Request and source advisory locks serialize cooperating completion calls. A conflicting request ID fails. The archive status and receipt commit in one transaction; failed requests leave neither partial record. Existing pending metadata can be completed after current proof validation; ready metadata is reused without replacing the archive object.

The private receipt retains the exact normalized proof packet, actor and server timestamp. It excludes caller session claims and tokens. UPDATE/DELETE triggers prevent replacing or deleting receipts through ordinary SQL writes. RLS explicitly denies access and application grants are absent. This is not WORM storage or a defense against the database owner.

The Edge worker validates the exact caller token through Auth.getUser before extracting a small allowlist of session claims. SQL accepts proof completion only in a service JWT context, then uses the forwarded authenticated caller context to recheck the actual database session, profile, current permissions and source scope. SQL trusts the privileged worker's byte verification; it does not read Storage itself and is not a medical review.
