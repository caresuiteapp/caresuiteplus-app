## Integrated result

The prepared Web flow now connects document selection, byte fingerprint capture, an independently confirmed source write, archive completion, existing-request recovery and historical download. A returned UUID alone does not mark source capture successful. The Web service reads the exact retained source through a separate own-request confirmation RPC and verifies tenant, client, medication, actor, request, complete original payload, document facts and native microsecond versions.

Source capture stores the complete native order and document snapshots with client-observed content hash/size. A private immutable receipt binds the source fingerprint and original request. Confirmed source rows cannot be changed or removed through ordinary SQL writes. Replay can recover the retained historical source after today's order changes; it cannot substitute today's facts or turn that source into current-order proof. Existing shared/native source capture behavior is preserved; the new route is Web-only.

The Web screen separates confirmed persistence from list refresh. Refresh failure leaves a confirmed result with a read-only refresh retry, rather than inviting another write. Capture proceeds explicitly to archive only after the refreshed list confirms the source and current-order eligibility. Ready current archives can be reverified. Historical-source downloads remain available, while new current-order archive actions stay blocked for stale source versions. New captions were shortened after inspecting the existing single-line button implementation; actual layout rendering remains unverified.

The production Edge entry uses the tested injectable gateway. Auth.getUser validates the exact user token before the archive-only privileged client is created. Original files and preparation/recovery RPCs use the caller's JWT; archive object upload/readback and atomic completion use the privileged client. Uploads do not overwrite existing objects. The same actual gateway code now runs against injected SDK-shaped transports in regression tests.

A previously committed archive request can now be recovered after a lost response even if the native document/order has since changed. The recovery RPC returns only that retained own request, checks the original source fingerprint and full ready archive identity under current own-scope authorization, and never labels it current clinical evidence. The worker reads the historical archive bytes, verifies hash and size, then repeats recovery and authorization. Missing or altered archive bytes cannot fall back to today's original document. A fresh request still follows current-source preparation and cannot reuse the recovery exception.

## Authorization and database changes

The source scope helper locks the current own profile/session, active client, active Pflege assignment, native medication and own role-permission rows through completion. Required rights are checked against the resolved own profile's role, avoiding reliance on the broader account-wide profile join in the legacy permission helper. No global permission implementation was changed. Source preparation also compares the complete captured document snapshot for newly receipted captures.

Raw timestamp spellings remain in original requests. Only parsing uses a copy with the supported native space separator normalized; this closes capture-to-archive failure for otherwise valid PostgreSQL metadata timestamps.
